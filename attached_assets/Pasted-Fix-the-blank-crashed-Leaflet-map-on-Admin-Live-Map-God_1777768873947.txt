Fix the blank/crashed Leaflet map on Admin → Live Map / God’s View.

Current problem:
The God’s View page loads the layout, cards, filters, and driver panel, but the map area is blank gray. Leaflet attribution appears, but map tiles/markers do not render. The page says “0 drivers on the map” even though Total Drivers shows 2.

This means there may be TWO bugs:
1. Leaflet map/tile rendering is broken.
2. Driver marker data/filtering is also broken.

Do not guess. Debug the map rendering first, then driver markers.

Critical requirements:
- Do NOT rebuild the whole page.
- Do NOT use fake driver data.
- Do NOT hardcode markers.
- Fix the root cause.
- Keep Leaflet/OpenStreetMap unless the app already has a different working map provider.
- After fixing, review the code and test.

Step 1 — Inspect browser console errors

Open the page and check console/network errors.

Look specifically for:
- Leaflet CSS not loaded
- Leaflet marker icon missing
- ResizeObserver errors
- window is not defined
- document is not defined
- Map container is already initialized
- Invalid LatLng object
- Cannot read properties of undefined
- Tile request blocked
- Mixed content
- CORS errors
- OpenStreetMap tile 403/404
- map container has zero height
- duplicate Leaflet imports
- SSR issue if using Next.js
- React-Leaflet version mismatch

Fix all map-related console errors.

Step 2 — Verify Leaflet CSS

Make sure Leaflet CSS is imported globally.

If using React/Vite:
Import in main entry file or app root:

import "leaflet/dist/leaflet.css";

If using Next.js:
Import it in the correct client/global place.

Without Leaflet CSS, map and icons may render incorrectly.

Step 3 — Verify map container height

The map container must have real height.

Check CSS:
- Parent div height
- MapContainer height
- flex/grid parent height
- overflow rules
- hidden tabs/panels
- collapsed container
- min-height

Set a stable height if needed:

.mapContainer {
  height: 600px;
  min-height: 600px;
  width: 100%;
}

Do not rely only on height: 100% unless every parent has height.

Step 4 — Verify MapContainer setup

Find the God’s View map component.

Make sure MapContainer has valid center and zoom:

<MapContainer
  center={[33.5731, -7.5898]}
  zoom={6}
  style={{ height: "100%", width: "100%" }}
>
  <TileLayer
    attribution="&copy; OpenStreetMap contributors"
    url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png"
  />
</MapContainer>

If the current center is undefined/null, fix with safe fallback center.

Use Morocco fallback center only when there are no valid driver/user coordinates.

Step 5 — Fix map resize/invalidation

If the map is inside a card, tab, responsive layout, or loads after data, Leaflet may need resize invalidation.

Add a small component inside MapContainer:

function ResizeMapFix() {
  const map = useMap();

  useEffect(() => {
    setTimeout(() => {
      map.invalidateSize();
    }, 200);
  }, [map]);

  return null;
}

Also call invalidateSize when:
- layout changes
- sidebar/filter changes
- map becomes visible
- drivers load

Step 6 — Fix SSR/client-only issue if applicable

If the project uses Next.js or SSR:
- Leaflet must run client-side only.
- The map component must have "use client".
- Dynamically import map component with ssr: false if needed.

Example:
const LiveMap = dynamic(() => import("./LiveMap"), { ssr: false });

Do not access window/document before client render.

Step 7 — Fix Leaflet marker icons

If markers are invisible because default icon URLs are broken, configure marker icons.

Example:
import L from "leaflet";
import markerIcon2x from "leaflet/dist/images/marker-icon-2x.png";
import markerIcon from "leaflet/dist/images/marker-icon.png";
import markerShadow from "leaflet/dist/images/marker-shadow.png";

delete L.Icon.Default.prototype._getIconUrl;

L.Icon.Default.mergeOptions({
  iconRetinaUrl: markerIcon2x,
  iconUrl: markerIcon,
  shadowUrl: markerShadow,
});

If using custom colored div icons, verify CSS and HTML.

Step 8 — Debug tile layer/network

Check Network tab for tile requests.

If OSM tile requests fail:
- Verify URL is correct
- Verify https
- Verify no ad blocker/CSP blocking
- Verify tile container is requesting z/x/y tiles
- Try fallback tile URL only if needed

Use standard OSM first:
https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png

Step 10 — Normalize driver data

Create one normalized driver array used by stats, list, and markers.

Do not let stats use one API result and markers use another.

Add helper:

normalizeDriverForGodView(driver)

Return:
- id
- name
- phone
- plate
- vehicle
- lat
- lng
- status
- isOnline
- hasValidLocation
- lastLocationAt

Coordinate rules:
- Convert lat/lng to Number
- Reject null/undefined/empty
- Reject invalid range
- Reject 0,0 unless intentionally valid

Status rules:
Map backend status values into:
- available
- not_available
- way_to_pickup
- arrived_pickup
- way_to_dropoff
- stale_location
- offline
- unknown
